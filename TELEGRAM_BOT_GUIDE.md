# 🤖 NERMA AI (`@NermaAI_bot`) — Документация, диагностика и материалы к защите проекта

Данный документ описывает архитектуру доработанного Telegram-бота **NERMA AI** на базе **GPT Researcher**, установленные корневые причины 7 наблюдений ручного тестирования, внесённые инженерные улучшения, определения метрик источников, чек-лист тестирования и шаблон сравнительного оценивания для университетской защиты.

---

## 1. Трассировка пути запроса (End-to-End Pipeline)

```
Telegram Update
  │
  ├─► 1. Приём запроса и изоляция настроек:
  │      `user_store.snapshot(user_id)` создаёт глубокую копию (`copy.deepcopy`) `UserSettings`
  │      и присваивает уникальный `request_id`. Изменение кнопок во время работы не меняет запущенную задачу.
  │      Конфигурация языка передаётся локально в `researcher.cfg.language` (без мутации глобального `os.environ`).
  │
  ├─► 2. Очередь и управление состояниями (`RequestState`):
  │      `queued` → `searching` → `writing` → `exporting` → `completed` | `partial` | `failed` | `cancelled`.
  │      К статусному сообщению прикреплена inline-кнопка `🛑 Отменить запрос` (`cancel:<request_id>`).
  │
  ├─► 3. Препроцессинг поискового запроса (`telegram_bot/query_utils.py`):
  │      `extract_search_intent(raw_prompt)`:
  │      • очищает длинный пользовательский промпт от мета-инструкций («Укажи ссылку...», «Answer in two sentences»,
  │        «Search using this exact query:», «Ответ дай на русском языке»), оставляя короткое поисковое ядро (до 12 слов);
  │      • извлекает явные операторы `site:domain.tld` и запросы на официальные домены (`python.org`, `microsoft.com`,
  │        `scikit-learn.org`, `arxiv.org`);
  │      • определяет регион поиска (`ru-ru` для кириллицы, `us-en` для латиницы вместо некорректного `wt-wt`).
  │
  ├─► 4. Поиск с ограниченным восстановлением (`gpt_researcher/retrievers/duckduckgo/duckduckgo.py`):
  │      • Попытка 1: целевой поиск (`site:<domain> <clean_query>` при запросе официального источника) + основной поиск;
  │      • Попытка 2 (при пустой выдаче/ошибке): 1 повтор с упрощённым ключевым запросом (`simplified_query`, `backend="html"`);
  │      • Попытка 3 (резервный источник): MediaWiki Search API (`ru.wikipedia.org` / `en.wikipedia.org`) или проверенный
  │        каталог официальной документации без молчаливого снятия обязательного доменного ограничения;
  │      • Проверка принадлежности URL официальному домену выполняется строго через `urllib.parse.urlparse(url).hostname`
  │        (точное совпадение или поддомен `.domain`, а не поиск подстроки).
  │
  ├─► 5. Чтение страниц и формирование контекста LLM:
  │      • В режиме `Quick` и `Outline` выполняется ограниченное по времени (`SCRAPE_TIMEOUT_SEC`) чтение топ-страниц;
  │      • В режиме `Deep Research` подзапросы жёстко привязаны к исходному вопросу пользователя (`_is_drifted_query`
  │        блокирует уход в посторонние версии вроде Python 3.15–3.16 при историческом вопросе о первой версии Python).
  │
  └─► 6. Верификация ссылок и единое представление (`telegram_bot/exporter.py` — `ResearchResultBundle`):
         • Каждый маркер `[n]` в тексте сверяется с реальным списком `SourceItem`; неподтверждённые `[n]` и выдуманные URL удаляются;
         • Отказ LLM или `0` найденных URL переводит запрос в состояние `failed` (без пометки «Готовый отчёт» и без создания файлов);
         • Если ответ получен из общих источников, но запрошенный официальный домен не найден — статус `partial` с явным предупреждением;
         • Чат и файлы (`DOCX`, `MD`, `PDF`) формируются из одного объекта `ResearchResultBundle`.
```

## 3. Определения счётчиков источников и состояний запроса

### 3.1. Три показателя работы с источниками
В каждом успешном или частичном отчёте (в чате и в экспортируемых файлах) отображаются три строго разграниченных показателя:
1. **🔗 Найдено уникальных URL (`unique_urls_found`)** — общее число уникальных валидных URL, полученных от поисковых провайдеров после применения доменных фильтров и дедупликации.
2. **📄 Успешно прочитано страниц (`pages_read_successfully`)** — число URL, для которых было фактически загружено и извлечено текстовое содержимое веб-страницы (`read_status == "full_page"`). **Использование только поисковых сниппетов (`read_status == "snippet"`) никогда не считается чтением полных страниц.**
3. **📌 Процитировано источников (`sources_cited`)** — число уникальных источников из библиографии (`[1]..[n]`), на которые есть подтверждённая ссылка в итоговом тексте ответа.

### 3.2. Состояния запроса (`RequestState`)
- `queued` — запрос принят, зафиксирован снимок настроек (`UserSettings.snapshot()`), ожидает слота семафора параллелизма.
- `searching` — выполняется поиск источников и (при необходимости) целевой поиск по официальному домену.
- `writing` — выполняется синтез текста отчёта или плана (Outline) по собранному контексту.
- `exporting` — выполняется генерация файлов (`DOCX`, `MD`, `PDF`) из проверенного `ResearchResultBundle`.
- `completed` — получен содержательный ответ, подтверждённый источниками (включая официальный домен, если он запрашивался). Только в этом состоянии отображается заголовок **«✅ Готовый отчёт»**.
- `partial` — получен ответ по проверенным источникам, однако запрошенный официальный домен не был найден в выдаче (отображается заголовок **«⚠️ Частичный отчёт»** и явное примечание).
- `failed` — поиск вернул 0 результатов, произошла ошибка провайдера/тайм-аут или модель отказалась отвечать из-за нехватки данных. Файлы с текстом ошибки **не создаются**.
- `cancelled` — запрос остановлен пользователем через кнопку `🛑 Отменить запрос` или команду `/cancel`.

### 3.3. Параметры конфигурации (`.env`)
Без раскрытия секретов поддерживаются следующие настраиваемые параметры:
- `QUEUE_TIMEOUT_SEC=30` — макс. время ожидания в очереди;
- `SEARCH_TIMEOUT_SEC=20` — тайм-аут одного поискового вызова;
- `SCRAPE_TIMEOUT_SEC=12` — тайм-аут загрузки веб-страниц в Quick/Outline;
- `LLM_TIMEOUT_SEC=60` — тайм-аут генерации ответа LLM;
- `REQUEST_TIMEOUT_QUICK_SEC=60`, `REQUEST_TIMEOUT_STANDARD_SEC=180`, `REQUEST_TIMEOUT_DEEP_SEC=240` — общие ограничения времени на запрос;
- `MAX_CONCURRENT_REQUESTS=3` — ограничение параллельных исследований;
- `QUICK_MAX_RESULTS=5`, `QUICK_MAX_SCRAPE_PAGES=3`, `QUICK_MAX_WORDS=220` — бюджет режима Quick;
- `DEEP_MAX_DEPTH=1`, `DEEP_MAX_BREADTH=2` — ограничение глубины и ширины Deep Research;
- `VERBOSE_QUERY_LOGS=false` — включение/выключение полного логирования текста запросов в `nerma.diagnostics`.

## 4. Автоматические тесты и чек-лист ручной проверки

### 4.1. Запуск автоматических тестов (13 сценариев с моками)
```bash
./.venv/bin/python -m unittest tests/test_telegram_bot.py -v
```
Покрытые сценарии в `tests/test_telegram_bot.py`:
1. `test_01_short_query_extraction_from_long_prompt` — выделение короткого поискового запроса из длинного промпта;
2. `test_02_explicit_site_domain_and_subdomains` — обработка `site:domain` и проверка поддоменов через `urlparse`;
3. `test_03_official_source_request_when_domain_found` — запрос официального источника (`python.org`), когда домен найден (`completed`);
4. `test_04_official_source_request_when_domain_not_found` — запрос официального источника (`microsoft.com`), когда домен не найден (`partial` + предупреждение);
5. `test_05_empty_search_refusal_not_marked_completed_and_no_export` — пустая выдача/отказ не помечается как «Готовый отчёт» и не создаёт DOCX/MD;
6. `test_06_citations_match_bibliography_in_chat_and_docx_md` — соответствие `[1], [2]` и списка URL в чате и DOCX/MD, удаление выдуманных ссылок;
7. `test_07_source_counters_found_read_cited_accuracy` — точность трёх счётчиков (найдено URL / прочитано страниц / процитировано);
8. `test_08_mode_switching_and_multi_user_settings_isolation` — изоляция настроек разных пользователей и неизменность снимка настроек уже запущенной задачи;
9. `test_09_quick_export_button_uses_saved_bundle_without_rerunning` — экспорт по кнопке в Quick использует сохранённый `ResearchResultBundle` без повторного запуска `GPTResearcher`;
10. `test_10_cancel_running_request_stops_delivery` — кнопка отмены останавливает задачу и предотвращает отправку запоздалого отчёта;
11. `test_11_search_or_scrape_timeout_handled_cleanly` — корректная обработка тайм-аута без зависания бота;
12. `test_12_deep_research_subqueries_stay_anchored_no_version_drift` — удержание подзапросов Deep Research в рамках истории первой версии Python без ухода в 3.15–3.16;
13. `test_13_secret_redaction_in_diagnostics` — маскирование токенов и API-ключей в диагностических логах.

### 4.2. Чек-лист ручной проверки в Telegram
- [ ] **Шаг 1 (Quick + официальный домен):** Выбрать режим `⚡ Быстрый обзор (Quick)`, отправить запрос про создателя Python с просьбой указать `python.org`. - [ ] **Шаг 3 (Явный `site:microsoft.com`):** Отправить запрос с `site:microsoft.com Microsoft founded 1975 Bill Gates Paul Allen`. Убедиться, что найден источник на `microsoft.com` / `news.microsoft.com`.
- [ ] **Шаг 4 (Режим Outline):** Переключить режим в `📝 План исследования (Outline)` и отправить тему. Убедиться, что бот выдаёт иерархический план разделов (I, II, III...) со ссылками `[n]`, а не длинное эссе.
- [ ] **Шаг 5 (Кнопка отмены):** Запустить `🧠 Глубокое исследование (Deep Research)` и нажать `🛑 Отменить запрос` на статусном сообщении. Убедиться, что статус меняется на `🚫 Запрос отменён` и отчёт после этого не приходит.

## 5. Материалы для университетской защиты проекта

### 5.1. Разделение запросов: Набор для разработки (Dev/Debug) vs Контрольный набор (Held-Out Test Set)
Чтобы оценка качества на защите была методологически честной (без переобучения эвристик под единственные тестовые фразы), запросы разделены на два независимых набора:

#### А. Отладочный / регрессионный набор (Dev Set — 7 сценариев из первичного тестирования)
1. *(RU, Quick, Official Domain)*: «В каком году вышла первая версия Python и кто создал этот язык? Укажи ссылку на официальный источник python.org, подтверждающий ответ.»
2. *(EN, Quick, Official Domain)*: «Who founded Microsoft, and in what year? Cite an official microsoft.com source. Answer in two sentences.»
3. *(EN, Quick, Explicit `site:`)*: «Search using this exact query: site:microsoft.com Microsoft founded 1975 Bill Gates Paul Allen. Who founded Microsoft and in what year? Cite a direct official source URL from microsoft.com or its subdomains. Answer in two sentences.»
4. *(RU, Standard, Primary Sources)*: «Кратко сравни TF-IDF и Word2Vec для классификации текста. Для каждого метода укажи принцип работы, одно преимущество и одно ограничение. Добавь две ссылки на первоисточники или официальную документацию.»
5. *(RU, Deep Research, Historical Scope)*: «История создания первой версии языка Python (0.9.0 и 1.0): предпосылки проекта ABC в CWI, ключевые архитектурные решения Гвидо ван Россума.»
6. *(RU, Outline)*: «Составь план исследования по теме: Методы борьбы с галлюцинациями больших языковых моделей (RAG, верификация цитат, консенсусное декодирование).»
7. *(Negative / Non-existent official domain)*: «Найди статью о квантовом компиляторе на сайте `site:nonexistent-domain-xyz-99999.org`.» (Ожидаемое поведение: честный статус `failed`, 0 файлов).

#### Б. Контрольный набор для финальной демонстрации (Held-Out Evaluation Set — новые темы и домены)
1. *(RU, Quick, Official Docs)*: «Кто разработал библиотеку PyTorch и какая организация управляет проектом сегодня? Приведи ссылку на официальный сайт `pytorch.org`.»
2. *(EN, Quick, Explicit `site:`)*: «site:djangoproject.com Who created the Django web framework and in what year was it publicly released? Answer in two sentences.»
3. *(RU, Standard, ML Comparison)*: «Сравни архитектуры Transformer (Attention Is All You Need) и рекуррентных сетей LSTM для задач обработки естественного языка: принцип работы, вычислительная сложность и ссылки на первоисточники.»
4. *(RU, Deep Research, Historical Scope)*: «История создания первой версии ядра Linux (0.01 в 1991 году) Линусом Торвальдсом и роль ОС MINIX.»
5. *(RU, Outline)*: «Разработай иерархический план обзора по теме: Метрики оценки качества систем Retrieval-Augmented Generation (RAGAS, Faithfulness, Citation Precision/Recall).»

### 5.2. Шаблон сравнительного оценивания: Базовая версия vs Доработанная система NERMA AI

| Критерий / Метрика | Базовая версия (исходный GPT Researcher + простой обёрточный бот) | Доработанная версия NERMA AI (текущая реализация) | Метод измерения на контрольном наборе |
|---|---|---|---|
| **1. Выполнение доменных ограничений (`Official Domain Recall`)** | Игнорировался `query_domains` в `Duckduckgo`; длинный промпт ломал `site:domain` | Целевой поиск `site:domain`, очистка поискового ядра, строгая проверка `urlparse(url).hostname` | Доля запросов с требованием официального домена, где в библиографии присутствует валидный URL этого домена |
| **2. Точность цитирования (`Citation Precision`)** | Маркеры `[1], [2]` в Quick не имели списка URL в DOCX; в Deep Research число `visited_urls` (45) не совпадало со списком литературы (14) | Единый `ResearchResultBundle`: 100% маркеров `[n]` в тексте и DOCX имеют соответствующий `[n] Title — URL`, выдуманные URL удаляются | $\frac{\text{Подтверждённые маркеры } [n]}{\text{Все маркеры } [n] \text{ в ответе}} \times 100\%$ |
| **3. Доля ложных «Готовых отчётов» при сбое поиска (`False-Positive Report Rate`)** | При 0 источников отказ LLM помечался как «📊 Готовый отчёт» и экспортировался в DOCX/MD | Строгий детектор `unique_urls_found == 0` и `is_refusal_or_empty_report()`: статус `failed`, 0 файлов с ошибкой | Доля запросов с пустой выдачей, ошибочно помеченных как `completed` (целевое значение: **0%**) |
| **4. Тематическая релевантность подзапросов Deep Research (`Sub-query On-Topic Rate`)** | Промпт принуждал искать «recent developments up to current_time», уводя исторический запрос про Python 0.9.0 в Python 3.15–3.16 | Привязка всех подзапросов к `Original User Question` + фильтр дрейфа версий `_is_drifted_query()` | Доля сгенерированных подзапросов, напрямую относящихся к временным и тематическим рамкам исходного вопроса |
| **5. Устойчивость и контроль времени выполнения (`Bounded Latency & Cancellation`)** | Зависание HTTP/2 пула блокировало запрос до 10–45 минут без возможности отмены | Тайм-ауты на очередь, поиск, скрапинг, LLM и весь запрос + кнопка `🛑 Отменить запрос` | Медианное / максимальное время ответа (сек) и время реакции на нажатие кнопки отмены |
| **6. Экономия вызовов поиска и токенов в Quick (`Search & Cost Efficiency`)** | Двойной вызов `quick_search` на каждый запрос + авто-экспорт файлов при каждом коротком вопросе | Одиночный поиск + экспорт DOCX/MD только по кнопке из кэша `SAVED_BUNDLES` без повторного запуска | Среднее число поисковых запросов и стоимость (`$`) на один запрос в режиме Quick |

### 5.3. Пояснение к университетскому требованию «Улучшение модели или датасета»

Если на защите действует формальное требование комиссии **«показать улучшение самой модели или датасета»** (помимо инженерной доработки пайплайна информационного поиска и верификации цитат), предусмотрены два чётких варианта позиционирования и развития работы:

- **Вариант А (Оценка и доработка RAG-пайплайна на стратифицированном бенчмарке — реализовано сейчас):**
  - В системах класса **Retrieval-Augmented Generation (RAG)** качество итогового ответа определяется совместной работой модуля формулирования запросов (*Query Rewriting*), ретривера (*Domain-Constrained Retrieval*), модуля чтения страниц и пост-процессора верификации ссылок (*Citation Grounding*).
  - Собран специализированный русско-английский оценочный датасет запросов с жёсткими ограничениями (требование официального домена, оператор `site:`, исторические рамки, многоаспектные сравнения), разделённый на *Dev* и *Held-Out* выборки, на котором измеряются метрики *Citation Precision*, *Official Domain Recall*, *Sub-query On-Topic Rate* и *False-Positive Report Rate*.

- **Вариант Б (Дообучение / адаптация локального компонента или сбор датасета пар «Промпт → Поисковый запрос / Верификация цитат» — при требовании обучения весов):**
  1. **Датасет `Query-Intent & Citation-Verification`:** На основе структурированных логов `nerma.diagnostics` и `ResearchResultBundle` формируется размеченный датасет пар:
     - вход: длинный пользовательский промпт на русском/английском языке с ограничениями;
     - целевой выход: JSON-структура `{clean_query, simplified_query, official_domains, is_historical_focus}` + разметка соответствия пар `(утверждение с [n], текст источника [n])` на классы `supported / unsupported`.
  2. **Дообучение легковесного классификатора / реранкера или LoRA-адаптера:**
     - На собранном датасете дообучается компактный кросс-энкодер (например, `BAAI/bge-reranker-v2-m3` или `rubert-tiny2`) для ранжирования прочитанных фрагментов перед подачей в LLM либо малая инструктивная модель (через QLoRA) для задачи сжатия пользовательского промпта в точный поисковый запрос.
     - Качество сравнивается по метрикам `nDCG@5`, `MRR` и `Citation Faithfulness` до и после адаптации.
